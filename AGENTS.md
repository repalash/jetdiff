# jetdiff: guidelines for agents

jetdiff shows code changes (GitHub pull requests, commits, compares) in an IDE-style side-by-side diff, on any
device, online or offline. It is a static web app with no build step: the files in this repository are served as
they are.

## Stack

- Vanilla ES modules in `js/`, `style.css`, `index.html`; `sw.js` is the service worker (the offline app)
- Monaco 0.52 (AMD build from jsDelivr), Shiki for TextMate highlighting, markdown-it and DOMPurify (from esm.sh),
  fflate for offline packs; libraries load from CDNs at fixed versions
- GitHub REST and GraphQL from the browser, with the user's token (stored in `localStorage`)
- Playwright for tests (`tests/`), against a recorded fixture of a public pull request

## Layout

| Path | What |
| --- | --- |
| `js/main.js` | the app: start page, toolbar, panels, settings, edits and commits, offline UI |
| `js/github.js` | GitHub API, snapshots and packs as a data source |
| `js/sbs.js` | the side-by-side viewer (two editors, connectors in the gutter) |
| `js/editor.js` | Monaco and Shiki loading, themes, languages |
| `js/markdown.js` | Markdown rendering and the rich Markdown diff |
| `js/tree.js`, `js/log.js`, `js/palette.js` | the file tree, the commit log, Search Everywhere |
| `js/offline.js`, `sw.js` | Download for offline, pack import, the service worker |
| `js/themes.js` | generated by `tools/material-themes.mjs`: do not edit by hand |
| `tools/` | the dev server, the snapshot recorder, the pack maker, the theme generator |
| `tests/` | Playwright tests; `tests/fixture/` is a recorded pull request (repalash/threepipe#193) |
| `docs/` | the README screenshots |
| `issues/open`, `issues/closed` | the backlog: one file per issue |

## Commands

| Command | What |
| --- | --- |
| `npm start` | dev server on port 3000 |
| `npm test` | the Playwright tests (must pass before a commit) |
| `npm run record -- <page url> <owner/repo/number> [name]` | record a snapshot into `snap/` |
| `npm run pack -- snap/<name> <out dir>` | make offline packs from a snapshot |
| `npm run themes -- <material-theme-ui-lite checkout>` | regenerate `js/themes.js` |

## Rules

- Find the source of a problem and fix it there; no workarounds stacked on workarounds.
- Read how the app already does something before adding to it, and follow that pattern.
- Comments explain a non-obvious why, briefly; no comments that restate the code.
- Ask before changing what is stored (storage keys, cache names, the snapshot and pack formats): saved data and
  existing packs must keep working.
- Verify before claiming something works: run it, and add a test when a behaviour is worth keeping.
- Every bug or idea found and not fixed goes into `issues/open` as its own file.
- Keep the README and the issue files true when the code changes.
- Git: work on a branch, never on `main` directly, unless asked; the maintainer merges.
- Snapshots and packs of private repositories hold their code: never commit them (`snap/` and `packs/` are ignored).
