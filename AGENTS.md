# jetdiff: guidelines for agents

jetdiff shows code changes (GitHub pull requests, commits, compares) in an IDE-style side-by-side diff, on any
device, online or offline. It is a static web app with no bundler: the app's files in this repository are served as
they are, and the build only copies them, with the libraries from `node_modules`, into `dist/`.

## Stack

- Vanilla ES modules in `js/`, `style.css`, `index.html`; `sw.js` is the service worker (the offline app, updated a
  whole release at a time: `js/update.js` tells the page a new one is ready)
- Libraries from npm at exact versions (package-lock.json), served by the site itself from `vendor/<name>@<version>/`:
  Monaco 0.52 (its AMD build), Shiki with its JavaScript regex engine, markdown-it, DOMPurify, fflate for offline
  packs, and the Inter and JetBrains Mono fonts (@fontsource). The ES modules import each other by name through the
  import map in `index.html`. Nothing loads from a CDN.
- A Content Security Policy on every page (`worker/headers.js`, sent by the Worker and the dev server alike): no
  inline scripts but the import map, allowed by its hash
- GitHub REST and GraphQL from the browser, with the user's token (stored in `localStorage`)
- Playwright for tests (`tests/`), against a recorded fixture of a public pull request

## Layout

| Path | What |
| --- | --- |
| `js/main.js` | the app: start page, toolbar, panels, settings, edits and commits, offline UI |
| `js/github.js` | GitHub API, snapshots and packs as a data source |
| `js/sbs.js` | the side-by-side viewer (two editors, connectors in the gutter) |
| `js/editor.js` | Monaco and Shiki loading, themes, languages |
| `js/markdown.js` | Markdown rendering and the rich Markdown diff |
| `js/tree.js`, `js/log.js`, `js/palette.js` | the file tree, the commit log, Search Everywhere |
| `js/offline.js`, `sw.js` | Download for offline, pack import, the service worker |
| `js/themes.js` | generated by `tools/material-themes.mjs`: do not edit by hand |
| `404.html`, `js/redirect.js` | turns a GitHub-style path (`/owner/repo/pull/1`) into the app's URL |
| `worker/`, `wrangler.jsonc` | the Cloudflare Worker that serves the site (static assets in `dist/`), its security headers (`worker/headers.js`) and Sign in with GitHub (`worker/auth.js`) |
| `tools/site.mjs` | what the site serves: the app's files, the libraries copied from `node_modules`, the import map, and `sw.js` with its release |
| `tools/` | also the dev server, the build, the snapshot recorder, the pack maker, the theme generator |
| `tests/` | Playwright tests; `tests/fixture/` is a recorded pull request (repalash/threepipe#193) |
| `docs/` | the README screenshots |
| `.github/` | CI (tests, then deploy from `main`), Dependabot's weekly updates, and `vendor.yml`, which runs `npm run vendor` on Dependabot's pull requests |
| `issues/open`, `issues/closed` | the backlog: one file per issue |

## Commands

| Command | What |
| --- | --- |
| `npm start` | dev server on port 3000 (the libraries from `node_modules`, as the build serves them) |
| `npm test` | the Playwright tests (must pass before a commit) |
| `npm run build` | copy the served files and the libraries into `dist/` (fails past the Worker's limits) |
| `npm run vendor` | after changing a library's version: write the versions into `index.html` and the import map's hash into `worker/headers.js` (`npm run vendor -- --check` only checks, as CI does) |
| `npm run deploy` | build and deploy the Worker (wrangler, needs Cloudflare access) |
| `npm run record -- <page url> <owner/repo/number> [name]` | record a snapshot into `snap/` |
| `npm run pack -- snap/<name> <out dir>` | make offline packs from a snapshot |
| `npm run themes -- <material-theme-ui-lite checkout>` | regenerate `js/themes.js` |

## Rules

- Find the source of a problem and fix it there; no workarounds stacked on workarounds.
- Read how the app already does something before adding to it, and follow that pattern.
- Comments explain a non-obvious why, briefly; no comments that restate the code.
- Ask before changing what is stored (storage keys, cache names, the snapshot and pack formats). jetdiff has no users
  yet: no migrations, fallbacks or compatibility code for older data or versions; ask if one seems needed.
- Verify before claiming something works: run it, and add a test when a behaviour is worth keeping.
- Every bug or idea found and not fixed goes into `issues/open` as its own file.
- Keep the README and the issue files true when the code changes.
- Git: commit directly to `main`; no pull requests or branches unless asked.
- New files the site serves go into `FILES` in `tools/site.mjs` and, for offline use, its `SHELL_FILES`. A new library
  goes into `package.json` at an exact version, and into `MODULES` (or `PREFIXES`) in `tools/site.mjs`; then `npm run
  vendor`.
- No inline scripts or event handler attributes: the Content Security Policy blocks them.
- Snapshots and packs of private repositories hold their code: never commit them (`snap/` and `packs/` are ignored).
